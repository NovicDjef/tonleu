## Vue d'ensemble

L'écosystème Node.js a beaucoup changé ces dernières années : nouveaux frameworks, nouveaux ORM, outillage intégré au runtime. Cet article passe en revue les briques que l'on assemble couramment pour une application full stack destinée à la production, de l'API jusqu'au déploiement.

## Le runtime Node.js

### Node.js 20 et plus

Node.js 20 LTS stabilise plusieurs fonctionnalités, dont le test runner intégré, apparu dans Node.js 18 :

```javascript
// Test runner intégré (Node.js 18+)
import { test, describe, before, after } from 'node:test';
import assert from 'node:assert';
import { once } from 'node:events';
import { app } from '../src/app.js';

describe('User API', () => {
  let server;
  let baseUrl;

  before(async () => {
    server = app.listen(0); // port libre attribué par le système
    await once(server, 'listening');
    const { port } = server.address();
    baseUrl = `http://localhost:${port}`;
  });

  after(() => server.close());

  test('should create user', async () => {
    const response = await fetch(`${baseUrl}/api/users`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ name: 'John Doe' })
    });
    assert.strictEqual(response.status, 201);
  });
});
```

## Frameworks web

### Next.js 14 : App Router et Route Handlers

Avec l'App Router, le front-end et les endpoints d'API cohabitent dans le même projet :

```typescript
// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { prisma } from '@/lib/prisma';
import { z } from 'zod';

const createUserSchema = z.object({
  name: z.string().min(2),
  email: z.string().email(),
});

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    const { name, email } = createUserSchema.parse(body);
    
    const user = await prisma.user.create({
      data: { name, email },
    });
    
    return NextResponse.json(user, { status: 201 });
  } catch (error) {
    return NextResponse.json(
      { error: 'Invalid input' },
      { status: 400 }
    );
  }
}
```

### Fastify 4.x : une alternative orientée performance

Fastify valide les requêtes et sérialise les réponses à partir de schémas JSON :

```typescript
import Fastify, { FastifyInstance } from 'fastify';
import { PrismaClient } from '@prisma/client';

const fastify: FastifyInstance = Fastify({
  logger: true
});

const prisma = new PrismaClient();

// Validation basée sur un schéma
const userSchema = {
  type: 'object',
  required: ['name', 'email'],
  properties: {
    name: { type: 'string', minLength: 2 },
    email: { type: 'string', format: 'email' }
  }
};

fastify.post('/api/users', {
  schema: {
    body: userSchema,
    response: {
      201: {
        type: 'object',
        properties: {
          id: { type: 'string' },
          name: { type: 'string' },
          email: { type: 'string' }
        }
      }
    }
  }
}, async (request, reply) => {
  const { name, email } = request.body as any;
  const user = await prisma.user.create({ data: { name, email } });
  reply.status(201).send(user);
});
```

## Couche de données et ORM

### Prisma

Prisma décrit le modèle de données dans un schéma unique, à partir duquel il génère un client typé :

```javascript
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        String   @id @default(cuid())
  name      String
  email     String   @unique
  posts     Post[]
  profile   Profile?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("users")
}

model Post {
  id        String   @id @default(cuid())
  title     String
  content   String?
  published Boolean  @default(false)
  authorId  String
  author    User     @relation(fields: [authorId], references: [id], onDelete: Cascade)
  tags      Tag[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("posts")
}
```

### Patterns Prisma avancés

```typescript
import { PrismaClient, Prisma } from '@prisma/client';

const prisma = new PrismaClient({
  log: ['query', 'info', 'warn', 'error'],
});

// Transaction avec rollback
export async function createUserWithProfile(userData: {
  name: string;
  email: string;
  bio?: string;
}) {
  return await prisma.$transaction(async (tx) => {
    const user = await tx.user.create({
      data: {
        name: userData.name,
        email: userData.email,
      },
    });

    const profile = await tx.profile.create({
      data: {
        bio: userData.bio || '',
        userId: user.id,
      },
    });

    return { user, profile };
  });
}

// Requêtes avancées avec relations
export async function getUserWithPosts(userId: string) {
  return await prisma.user.findUnique({
    where: { id: userId },
    include: {
      posts: {
        where: { published: true },
        orderBy: { createdAt: 'desc' },
        take: 10,
        include: {
          tags: true,
        },
      },
      _count: {
        select: {
          posts: { where: { published: true } },
        },
      },
    },
  });
}
```

### Drizzle ORM : une alternative plus légère

Drizzle définit les tables directement en TypeScript et reste proche du SQL :

```typescript
import { drizzle } from 'drizzle-orm/postgres-js';
import { pgTable, text, timestamp, boolean, uuid } from 'drizzle-orm/pg-core';
import { eq, desc } from 'drizzle-orm';

export const users = pgTable('users', {
  id: uuid('id').primaryKey().defaultRandom(),
  name: text('name').notNull(),
  email: text('email').unique().notNull(),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

export const posts = pgTable('posts', {
  id: uuid('id').primaryKey().defaultRandom(),
  title: text('title').notNull(),
  content: text('content'),
  published: boolean('published').default(false),
  authorId: uuid('author_id').references(() => users.id),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

const db = drizzle(connection);

// Requêtes typées
export async function getUserPosts(userId: string) {
  return await db
    .select()
    .from(posts)
    .where(eq(posts.authorId, userId))
    .orderBy(desc(posts.createdAt));
}
```

## Authentification et sécurité

### Auth.js (NextAuth.js v5)

```typescript
// auth.config.ts
import { NextAuthConfig } from 'next-auth';
import GitHub from 'next-auth/providers/github';
import Google from 'next-auth/providers/google';
import Credentials from 'next-auth/providers/credentials';
import { compare } from 'bcryptjs';

export default {
  providers: [
    GitHub,
    Google,
    Credentials({
      async authorize(credentials) {
        const user = await getUserByEmail(credentials.email);
        if (user && await compare(credentials.password, user.password)) {
          return { id: user.id, email: user.email, name: user.name };
        }
        return null;
      },
    }),
  ],
  session: { strategy: 'jwt' },
  callbacks: {
    async session({ token, session }) {
      if (token.sub) {
        session.user.id = token.sub;
      }
      return session;
    },
  },
} satisfies NextAuthConfig;
```

### JWT et jetons de rafraîchissement

Un jeton d'accès de courte durée, couplé à un jeton de rafraîchissement stocké dans Redis, ce qui permet de le révoquer côté serveur :

```typescript
import jwt from 'jsonwebtoken';
import { Redis } from 'ioredis';

const redis = new Redis(process.env.REDIS_URL);

export interface TokenPair {
  accessToken: string;
  refreshToken: string;
}

export async function generateTokens(userId: string): Promise<TokenPair> {
  const accessToken = jwt.sign(
    { userId, type: 'access' },
    process.env.JWT_SECRET!,
    { expiresIn: '15m' }
  );

  const refreshToken = jwt.sign(
    { userId, type: 'refresh' },
    process.env.JWT_REFRESH_SECRET!,
    { expiresIn: '7d' }
  );

  // Stockage du jeton de rafraîchissement dans Redis
  await redis.setex(`refresh_token:${userId}`, 7 * 24 * 60 * 60, refreshToken);

  return { accessToken, refreshToken };
}

export async function refreshAccessToken(refreshToken: string) {
  try {
    const decoded = jwt.verify(refreshToken, process.env.JWT_REFRESH_SECRET!) as any;
    const storedToken = await redis.get(`refresh_token:${decoded.userId}`);
    
    if (storedToken !== refreshToken) {
      throw new Error('Invalid refresh token');
    }

    return generateTokens(decoded.userId);
  } catch (error) {
    throw new Error('Token refresh failed');
  }
}
```

## Temps réel

### WebSocket avec Socket.IO

L'adaptateur Redis permet de diffuser les événements entre plusieurs instances du serveur :

```typescript
import { Server } from 'socket.io';
import { createAdapter } from '@socket.io/redis-adapter';
import { Redis } from 'ioredis';

const pubClient = new Redis(process.env.REDIS_URL);
const subClient = pubClient.duplicate();

export function initializeSocket(httpServer: any) {
  const io = new Server(httpServer, {
    cors: {
      origin: process.env.FRONTEND_URL,
      credentials: true,
    },
  });

  io.adapter(createAdapter(pubClient, subClient));

  io.use(async (socket, next) => {
    try {
      const token = socket.handshake.auth.token;
      const user = await verifyJWT(token);
      socket.data.user = user;
      next();
    } catch (error) {
      next(new Error('Authentication failed'));
    }
  });

  io.on('connection', (socket) => {
    console.log(`User ${socket.data.user.id} connected`);

    socket.on('join_room', (roomId: string) => {
      socket.join(`room_${roomId}`);
    });

    socket.on('send_message', async (data) => {
      const message = await saveMessage(data);
      io.to(`room_${data.roomId}`).emit('new_message', message);
    });
  });

  return io;
}
```

### Server-Sent Events (SSE)

Pour des notifications unidirectionnelles du serveur vers le client, les SSE suffisent souvent :

```typescript
// app/api/notifications/route.ts
export async function GET(request: NextRequest) {
  const userId = getUserIdFromRequest(request);
  
  const encoder = new TextEncoder();
  let heartbeat: ReturnType<typeof setInterval>;
  let sendNotification: (notification: unknown) => void;

  const stream = new ReadableStream<Uint8Array>({
    start(controller) {
      sendNotification = (notification) => {
        controller.enqueue(encoder.encode(`data: ${JSON.stringify(notification)}\n\n`));
      };

      // Abonnement aux notifications
      subscribeToUserNotifications(userId, sendNotification);

      // Heartbeat toutes les 30 s
      heartbeat = setInterval(() => {
        controller.enqueue(encoder.encode(': heartbeat\n\n'));
      }, 30000);
    },
    // Appelée quand le client ferme la connexion
    cancel() {
      clearInterval(heartbeat);
      unsubscribeFromUserNotifications(userId, sendNotification);
    },
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
    },
  });
}
```

## Tâches de fond et files d'attente

### BullMQ avec Redis

```typescript
import { Queue, Worker, Job } from 'bullmq';
import { Redis } from 'ioredis';

// BullMQ exige maxRetriesPerRequest: null pour les workers
const connection = new Redis(process.env.REDIS_URL, {
  maxRetriesPerRequest: null,
});

// File d'attente des courriels
export const emailQueue = new Queue('email', { connection });

// Types de tâches
interface EmailJob {
  to: string;
  subject: string;
  template: string;
  data: Record<string, any>;
}

// Ajout d'une tâche à la file
export async function sendEmail(emailData: EmailJob) {
  await emailQueue.add('send_email', emailData, {
    attempts: 3,
    backoff: {
      type: 'exponential',
      delay: 2000,
    },
  });
}

// Worker qui traite les tâches
const emailWorker = new Worker(
  'email',
  async (job: Job<EmailJob>) => {
    const { to, subject, template, data } = job.data;
    
    // Envoi du courriel
    await sendEmailWithTemplate(to, subject, template, data);
    
    // Mise à jour de la progression
    job.updateProgress(100);
  },
  { connection }
);

emailWorker.on('completed', (job) => {
  console.log(`Email job ${job.id} completed`);
});

emailWorker.on('failed', (job, err) => {
  console.error(`Email job ${job?.id} failed:`, err);
});
```

## Stratégies de mise en cache

### Patterns de cache avec Redis

```typescript
import { Redis } from 'ioredis';

const redis = new Redis(process.env.REDIS_URL);

// Pattern cache-aside
export async function getUserById(id: string) {
  const cacheKey = `user:${id}`;
  
  // Lecture dans le cache en premier
  const cached = await redis.get(cacheKey);
  if (cached) {
    return JSON.parse(cached);
  }
  
  // Lecture en base de données
  const user = await prisma.user.findUnique({ where: { id } });
  
  // Mise en cache du résultat
  if (user) {
    await redis.setex(cacheKey, 3600, JSON.stringify(user)); // TTL d'une heure
  }
  
  return user;
}

// Pattern write-through
export async function updateUser(id: string, data: any) {
  const user = await prisma.user.update({
    where: { id },
    data,
  });
  
  // Mise à jour du cache
  const cacheKey = `user:${id}`;
  await redis.setex(cacheKey, 3600, JSON.stringify(user));
  
  return user;
}

// Invalidation du cache
export async function deleteUser(id: string) {
  await prisma.user.delete({ where: { id } });
  
  // Suppression de l'entrée en cache
  await redis.del(`user:${id}`);
}
```

## Conclusion

Une application full stack Node.js s'articule autour de quelques principes :

1. **Typage de bout en bout** : TypeScript partout, avec Prisma ou Drizzle pour l'accès aux données.
2. **Performance** : Fastify, mise en cache et requêtes optimisées.
3. **Expérience de développement** : tests intégrés au runtime et observabilité dès le départ.
4. **Montée en charge** : files d'attente et fonctionnalités temps réel distribuées avec Redis.
5. **Sécurité** : authentification éprouvée et validation systématique des entrées.

L'écosystème continue d'évoluer, notamment avec des runtimes comme Bun et Deno et le déploiement en périphérie (edge), qui changent la façon de construire et de déployer ces applications.
