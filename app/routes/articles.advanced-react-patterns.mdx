## TypeScript dans l'écosystème React en 2024

Cet article regroupe des patterns TypeScript que l'on retrouve aujourd'hui dans les projets React, Next.js (App Router) et React Native (versions 0.73 et suivantes). L'objectif : typer correctement chaque couche, du composant serveur jusqu'aux tests.

## React et TypeScript : les nouveautés

### Server Components avec TypeScript

Les Server Components, utilisables en production via l'App Router de Next.js et stabilisés dans React 19, amènent leurs propres conventions de typage. Un composant serveur peut être une fonction `async` :

```tsx
// Server Component correctement typé
interface ServerComponentProps {
  userId: string;
  searchParams: { [key: string]: string | string[] | undefined };
}

export default async function UserProfile({ userId, searchParams }: ServerComponentProps) {
  const user = await fetchUser(userId);
  return <div>{user.name}</div>;
}
```

### Fonctionnalités concurrentes et TypeScript

Les hooks concurrents `useTransition` et `useDeferredValue`, introduits avec React 18, s'utilisent ainsi avec TypeScript :

```tsx
function SearchResults() {
  const [query, setQuery] = useState('');
  const [isPending, startTransition] = useTransition();
  const deferredQuery = useDeferredValue(query);
  
  const handleSearch = (value: string) => {
    startTransition(() => {
      setQuery(value);
    });
  };
}
```

## TypeScript avec Next.js

### App Router

Avec l'App Router, chaque segment de route reçoit `params` et `searchParams`, que l'on peut typer explicitement :

```tsx
// app/users/[id]/page.tsx
// Depuis Next.js 15, params et searchParams sont des Promise
interface PageProps {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>;
}

export default async function UserPage({ params }: PageProps) {
  const { id } = await params;
  return <div>User {id}</div>;
}

// Génération des paramètres statiques avec TypeScript
export async function generateStaticParams(): Promise<{ id: string }[]> {
  const users = await fetchUsers();
  return users.map(user => ({ id: user.id }));
}
```

### Server Actions avec TypeScript

Une Server Action peut déclarer explicitement ses entrées et sa valeur de retour :

```tsx
'use server'

interface CreateUserInput {
  name: string;
  email: string;
}

type CreateUserResult = { success: boolean; id?: string };

// Appelée via <form action={createUser}> : reçoit le FormData natif
export async function createUser(formData: FormData): Promise<CreateUserResult> {
  const input: CreateUserInput = {
    name: String(formData.get('name') ?? ''),
    email: String(formData.get('email') ?? ''),
  };

  if (!input.name || !input.email) {
    return { success: false };
  }

  const user = await db.user.create({ data: input });
  return { success: true, id: user.id };
}
```

### Route Handlers

```tsx
// app/api/users/route.ts
export async function GET(request: NextRequest): Promise<NextResponse> {
  const users = await fetchUsers();
  return NextResponse.json(users);
}

export async function POST(request: NextRequest): Promise<NextResponse> {
  const body: CreateUserRequest = await request.json();
  const user = await createUser(body);
  return NextResponse.json(user, { status: 201 });
}
```

## TypeScript avec React Native

### Nouvelle architecture

La nouvelle architecture de React Native (Fabric et TurboModules) repose sur des spécifications TypeScript à partir desquelles Codegen génère le code natif :

```tsx
// Interface d'un TurboModule
interface NativeModule extends TurboModule {
  getConstants(): { [key: string]: any };
  getString(input: string): Promise<string>;
}

// Composant Fabric
interface NativeComponentProps {
  color: string;
  onPress: () => void;

```

### Code multiplateforme

Des implémentations propres à chaque plateforme, partageant le même contrat de props :

```tsx

  title: string;
  onPress: () => void;
  style?: ViewStyle;

export const PlatformButton: React.FC<PlatformButtonProps> = ({ title, onPress, style }) => {
  return (
    <Pressable onPress={onPress} style={style}>
      <Text>{title}</Text>
    </Pressable>
  );
```


## Patterns TypeScript avancés pour React

### Composants génériques avec contraintes

```tsx
interface DataTableProps<T extends Record<string, unknown>> {
  data: T[];
  columns: Array<{
    key: keyof T;
    title: string;
    render?: (value: T[keyof T], item: T) => React.ReactNode;
  }>;
}

function DataTable<T extends Record<string, unknown>>({ data, columns }: DataTableProps<T>) {
  return (
    <table>
      {data.map((item, index) => (
        <tr key={index}>
          {columns.map(column => (
            <td key={String(column.key)}>
              {column.render ? column.render(item[column.key], item) : String(item[column.key])}
            </td>
          ))}
        </tr>
      ))}
    </table>
  );
}
```

### Formulaires avec TypeScript

```tsx
const userSchema = z.object({

  email: z.string().email(),

type UserFormData = z.infer<typeof userSchema>;

function UserForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<UserFormData>({
    resolver: zodResolver(userSchema)
  });

  const onSubmit = (data: UserFormData) => {
    // Soumission du formulaire typée
  };
}
```

## Tester des composants React en TypeScript

### Vitest et Testing Library

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';

interface ButtonProps {
  onClick: () => void;
  children: React.ReactNode;
  variant?: 'primary' | 'secondary';
}

const Button: React.FC<ButtonProps> = ({ onClick, children, variant = 'primary' }) => (
  <button onClick={onClick} data-variant={variant}>
    {children}
  </button>
);

describe('Button Component', () => {
  it('should call onClick when clicked', async () => {
    const handleClick = vi.fn();
    render(<Button onClick={handleClick}>Click me</Button>);
    
    await userEvent.click(screen.getByRole('button'));
    expect(handleClick).toHaveBeenCalledOnce();
  });
});
```

## Conclusion

TypeScript évolue au même rythme que React, Next.js et React Native. Des Server Components à la nouvelle architecture de React Native, ces patterns aident à garder une base de code lisible et maintenable à mesure qu'elle grandit.

En résumé :

1. **Les Server Components** imposent de repenser le typage des données côté serveur.
2. **L'App Router de Next.js** permet de typer routes, paramètres et Server Actions.
3. **La nouvelle architecture de React Native** demande de comprendre TurboModules et Fabric.
4. **Les composants génériques** et un état bien typé limitent les erreurs à l'exécution.
5. **Des tests écrits en TypeScript** rendent les refactorisations plus sûres.
